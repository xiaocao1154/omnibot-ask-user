# Ask-User — 智能需求澄清

> 不猜测，不假设，不跳步。用填空题收集事实，用选择题确认偏好，两步走完再动手。

## 核心流程

```
用户模糊请求 → Agent 判断需求完整性 → 缺少信息则触发提问
  → Round 1: 填空题（收集硬性事实） → 等待回复
  → Round 2: 选择题（确认风格偏好） → 等待回复
  → 汇总确认 → 用户确认 → 执行任务
```

## 触发条件

当用户请求中 **≥2 个关键信息缺失**时触发：
- 任务目标不明确
- 执行方式有多种选择
- 用户偏好未确认
- 有隐含约束未知

**不需要触发**的情况：用户需求已完整明确、简单查询、用户说"你自己决定"。

## 八种提问策略

| # | 策略 | 格式 | 适用场景 |
|---|------|------|----------|
| 1 | **多选** | A/B/C/D + 自定义 | 有 2-5 个明确方向 |
| 2 | **大输入框** | 长文本区域 | 信息严重不足 |
| 3 | **分维度追问** | 多维度并列 | 复杂项目 |
| 4 | **渐进式** | 1 题/轮 | 需要逐步深入 |
| 5 | **假设确认** | "我建议 XX，可以吗？" | 有明显最优路径 |
| 6 | **决策树** | 分支选择 | 有明确流程分支 |
| 7 | **结果导向** | "你最终想要什么效果？" | 目标不清晰 |
| 8 | **控件描述** | 精确参数填空 | 需要精确规格 |

### 选择策略的规则

- 信息极少（只说"做个网站"）→ 优先「大输入框」或「结果导向」
- 有明显方向 → 优先「多选」
- 复杂多维 → 用「分维度」或「渐进式」
- 有最优路径 → 用「假设确认」
- 有明确分支 → 用「决策树」
- 目标不清 → 用「结果导向」

## 输出格式

### 填空题
```
❓ Q{n}/{total} — {问题}
   {提示/示例}
```

### 选择题
```
❓ Q{n}/{total} — {问题}

   A) {选项} — {特点}
   B) {选项} — {特点}
   C) {选项} — {特点}
   D) 📝 其他 — 告诉我你的想法
```

### 确认汇总
```
📝 需求确认：

✅ {字段1}: {值}
✅ {字段2}: {值}
✅ {字段3}: {值}

以上正确吗？回复"确认"我立即开始，或告诉我需要修改的地方。
```

## 回复解析规则

### 填空题
- 直接文字 → 存为答案
- "跳过"/"你定"/"随便" → 用默认值

### 选择题
- 字母（A/B/C...）→ 匹配选项
- 数字（1/2/3...）→ 匹配选项
- 关键词 → 模糊匹配
- "其他" → 追问具体方案

### 确认题
- "确认"/"对"/"ok"/"可以" → 确认
- "不"/"修改" + 具体内容 → 更新字段

## 限制

- 单轮最多 **6 个问题**
- 最多 **3 轮提问**，之后用默认值补齐
- 选择题选项按**推荐程度排序**（第一个最推荐）
- 选择题始终提供「其他/自定义」选项

## 内置场景模板

### 做网站
1. 网站主题/用途（填空，必填）
2. 目标受众（填空，必填）
3. 视觉风格（选择：苹果/终端/PPT/抖音）
4. 页面数量（选择：单页/3-5页/10+页）
5. 后端需求（选择：纯静态/简单后端/完整后端）
6. 其他补充（填空，选填）

### 写邮件
1. 收件人（填空，必填）
2. 邮件主题（填空，必填）
3. 核心内容（填空，必填）
4. 语气（选择：正式/友好/简洁）

### 做海报
1. 用途（填空，必填）
2. 文字内容（填空，必填）
3. 视觉风格（选择：中国风/简约/活泼）
4. 尺寸（选择：竖屏/横屏/方形）

### 写脚本
1. 功能描述（填空，必填）
2. 输入（填空，必填）
3. 输出（填空，必填）
4. 语言（选择：Python/JS/Shell）

### 做 PPT
1. 主题（填空，必填）
2. 页数（填空，必填）
3. 受众（填空，必填）
4. 风格（选择：商务/创意/数据）
5. 素材（选择：有/没有）

### 写文档
1. 主题（填空，必填）
2. 读者（填空，必填）
3. 格式（选择：Word/PDF/Markdown）
4. 篇幅（选择：简短/中等/详细）

## 与其他 Skill 的关系

- **grilling** 是质疑已有方案（压力测试），**ask-user** 是收集缺失信息（需求澄清）
- **brainstorming** 是发散探索，**ask-user** 是收敛确认
- 与 **Permission Manager** 集成：高风险操作的选择题中加入确认环节
